1. **Operand Purpose**:  
   Operands specify **source values** for an operation and the **destination** where the result is stored.

2. **Three Operand Types**:
   - **Immediate**: Constant values, written as `$Imm` (e.g., `$-577`, `$0x1F`).  
   - **Register**: Values stored in CPU registers, denoted as `ra`, with value `R[ra]`. x86-64 has 16 general-purpose registers usable in 64-, 32-, 16-, or 8-bit forms.
   - **Memory**: Values stored in memory, accessed via an **effective address**. Notation: `M[Addr]`.

3. **Memory Addressing Modes** (all special cases of a general form):  
   The most general memory operand format is:  
   ```
   Imm(rb, ri, s)
   ```  
   Which computes the effective address as:  
   ```
   Imm + R[rb] + R[ri] * s
   ```  
   - `Imm`: Immediate offset (constant)  
   - `rb`: Base register  
   - `ri`: Index register  
   - `s`: Scale factor (must be 1, 2, 4, or 8)

   Common simpler forms include:
   - `(ra)` → indirect: `M[R[ra]]`
   - `Imm` → absolute: `M[Imm]`
   - `Imm(rb)` → base + displacement
   - `(rb, ri)` → indexed: `M[R[rb] + R[ri]]`
   - `(, ri, s)` → scaled indexed without base

4. **Usage Context**:  
   These addressing modes are especially useful for **accessing array elements**, where the scale factor corresponds to the size of each element (e.g., 4 for 32-bit integers, 8 for 64-bit pointers).

In short, x86-64 provides **flexible operand forms** to efficiently encode constants, register values, and complex memory addresses—enabling compact and powerful low-level programming.



###  什么是数据移动指令？

这些指令的作用很简单：**把数据从一个地方复制到另一个地方**，比如：
- 从内存 → 寄存器
- 从寄存器 → 内存
- 寄存器 ↔ 寄存器

它们 **不会修改数据本身**，只是“搬运”。

关键优势：**一条指令能处理多种情况**，这要归功于 x86-64 灵活的操作数语法。

---

###  `mov` 指令家族：基本复制操作

最基础的数据移动指令是 `mov`。但它有 **四个变体**，区别在于操作的 **数据大小（字节数）**：

| 指令     | 移动字节数 | 含义             |
|----------|------------|------------------|
| `movb`   | 1 字节     | 移动一个字节（byte） |
| `movw`   | 2 字节     | 移动一个字（word）  |
| `movl`   | 4 字节     | 移动双字（doubleword / long） |
| `movq`   | 8 字节     | 移动四字（quadword） |

> 💡 指令末尾的字母（`b`/`w`/`l`/`q`）表示操作的数据大小。

####  示例：
```asm
movl $0x4050, %eax        # 把常量 0x4050 复制到 %eax（4 字节）
movw %bp, %sp             # 把 %bp 的低 2 字节复制到 %sp
movb (%rdi,%rcx), %al     # 从内存地址 (%rdi + %rcx) 读 1 字节到 %al
movb $-17, (%esp)         # 把 -17（作为 1 字节）写入内存地址 %esp
movq %rax, -12(%rbp)      # 把 %rax（8 字节）写入内存地址 %rbp - 12
```

####  重要规则：
> **不能直接从内存复制到内存！**  
> 即：**源操作数和目标操作数不能同时是内存地址**。

所以，如果想把一个内存位置的数据复制到另一个内存位置，必须分两步：
1. 先从源内存 → 寄存器
2. 再从寄存器 → 目标内存

例如：
```asm
movq (%rsi), %rax    # 第一步：从源内存加载到寄存器
movq %rax, (%rdi)    # 第二步：从寄存器存储到目标内存
```

###  `movl` 的特殊行为（32 位移动）

当你用 `movl` 向 **寄存器** 写入 4 字节数据时，会发生一件特别的事：

> **CPU 会自动把该 64 位寄存器的高 32 位清零！**

这是 x86-64 架构的规定：**任何对 32 位寄存器（如 `%eax`）的写操作，都会清零其所在 64 位寄存器（如 `%rax`）的高 32 位**。

例子：
```asm
movabsq $0x0011223344556677, %rax   # %rax = 0x0011223344556677
movl    $-1, %eax                    # %eax = 0xFFFFFFFF → 但 %rax 变成 0x00000000FFFFFFFF
```
虽然我们只写了 `%eax`，但 CPU 自动把高 32 位设为 0。

> ❗ 注意：`movb` 和 `movw` **不会**清零高位——它们只改写指定的字节，其余部分保持不变。



### 把小数据放进大空间：两种方式

有时你想把一个 **小值**（比如 1 或 2 字节）放进一个 **更大的寄存器**（比如 4 或 8 字节）。这时你有两个选择：


#### 1. **零扩展（Zero Extension）→ 用 `movz...`**
- 高位用 **0 填充**
- 适用于 **无符号数**

示例：
- `movzbl %al, %eax`：把 `%al` 中的 1 字节零扩展为 4 字节放入 `%eax`
- `movzbq %al, %rax`：1 字节 → 8 字节，高位补 0

常见指令：
| 指令       | 源 → 目标        | 效果示例（十六进制）       |
|------------|------------------|----------------------------|
| `movzbw`   | byte → word (2B) | `0xFF` → `0x00FF`          |
| `movzbl`   | byte → long (4B) | `0xFF` → `0x000000FF`      |
| `movzbq`   | byte → quad (8B) | `0xFF` → `0x00000000000000FF` |
| `movzwq`   | word → quad      | `0xABCD` → `0x000000000000ABCD` |

> ❗ 注意：**没有 `movzlq`**（4 字节 → 8 字节零扩展）这条指令。  
> 但你 **不需要它**！因为你可以直接用 `movl %eax, %rax` —— 它会自动把高 32 位清零！


#### 2. **符号扩展（Sign Extension）→ 用 `movs...`**
- 高位用 **符号位（最高位）填充**
- 适用于 **有符号整数**，保持数值不变

例子：
- 如果一个字节是 `-5`（二进制 `11111011`，即 `0xFB`），符号扩展到 4 字节后变成 `0xFFFFFFFB`，仍然是 -5。

常见指令：
- `movsbl %al, %eax`：字节 → 双字（符号扩展）
- `movsbq %al, %rax`：字节 → 四字
- `movswl %ax, %eax`：字 → 双字
- `movslq %eax, %rax`：双字 → 四字（4 字节 → 8 字节符号扩展）

还有一个快捷指令：
- `cltq`：等价于 `movslq %eax, %rax`，但编码更短（无需写操作数）。


### 关键总结表

| 概念 | 规则 |
|------|------|
| **基本 `mov`** | 根据后缀（`b/w/l/q`）决定操作大小 |
| **内存 → 内存？** | ❌ 不允许！必须通过寄存器中转 |
| **`movl` 写寄存器** | ✅ 自动清零 64 位寄存器的高 32 位 |
| **小 → 大（无符号）** | 用 `movz...`（高位补 0） |
| **小 → 大（有符号）** | 用 `movs...`（高位复制符号位） |
| **4 字节 → 8 字节零扩展** | 直接用 `movl %reg, %reg` 即可 |
| **`cltq`** | 快速将 `%eax` 符号扩展到 `%rax` |

###  为什么这很重要？
掌握这些指令能让你：
- 正确地在不同数据大小之间转换
- 区分有符号和无符号数的处理方式
- 理解编译器生成的汇编代码
- 编写或调试底层系统程序（如操作系统、驱动、性能关键代码）

#### **数据传送示例**
#### 总结：**数据移动示例 —— `exchange` 函数**

这个例子展示了在 x86-64 汇编中如何使用**数据移动指令**（特别是 `movq`）来实现一个通过指针交换值的简单 C 函数。



####  **C 代码**
```c
long exchange(long *xp, long y) {
    long x = *xp;  // 读取 xp 所指向的值
    *xp = y;       // 将 y 存入该地址
    return x;      // 返回原始值
}
```


####  **汇编代码（由 GCC 生成）**
```asm
exchange:
    movq (%rdi), %rax   # 将 *xp 加载到 %rax（作为返回值）
    movq %rsi, (%rdi)   # 将 y 存入 *xp 所指向的内存
    ret                 # 返回（返回值在 %rax 中）
```

- **参数传递规则（x86-64 System V ABI）**：
  - 指针 `xp` → 通过寄存器 `%rdi` 传入
  - 值 `y` → 通过寄存器 `%rsi` 传入
- **返回值**：放在寄存器 `%rax` 中



####  **关键要点**

1. **C 中的“指针”就是地址**  
   - 在汇编中，C 的指针只是一个存储在寄存器中的**内存地址**（例如 `%rdi` 保存了 `xp` 的地址）。
   - 对指针解引用（deferencing）（`*xp`）是通过**内存寻址操作** `(%rdi)` 实现的。

2. **局部变量通常保存在寄存器中**  
   - 局部变量 `x` **并未分配内存**，而是直接保存在寄存器 `%rax` 中。
   - 这避免了较慢的内存访问，提高了执行效率。

3. **`movq` 的两种基本用法**：
   - **从内存加载到寄存器**：`movq (%rdi), %rax`
   - **从寄存器存储到内存**：`movq %rsi, (%rdi)`

4. **高效简洁**  
   - 整个函数仅使用**两条数据移动指令**和一条 `ret` 指令。
   - 无需为局部变量分配栈空间或访问内存。

 **Important thing** 
 we cannot truncate from higher bit to lower for example unsigned to unsigned char. usigned 32 bit and char just 8 bit.
 ####  核心结论
此例清晰地说明了 C 语言中的指针解引用和局部变量操作是如何直接映射为高效的、基于寄存器的数据移动汇编指令的，体现了高级语言与底层机器代码之间的紧密联系，也展示了系统级编程中性能优化的基本思想。


#### **总结：x86-64 中的堆栈压入（push）与弹出（pop）操作**

程序中的**堆栈（stack）** 是一种非常重要的数据结构，用于管理函数调用、局部变量和临时数据。它遵循 **“后进先出”（LIFO, Last-In First-Out）** 的原则：最后被放入的数据，最先被取出。


### x86-64 中堆栈的工作方式

- 堆栈存储在普通内存中。
- 它**向下增长**——即向**更低的内存地址**方向扩展。
- **栈顶指针**由寄存器 **`%rsp`** 保存，它始终指向**当前栈顶元素的地址**（即最近一次压入的数据所在位置）。
- 按照惯例，图示中堆栈是**倒着画的**：栈顶画在底部，因为它的地址数值最小。



####  `pushq` 指令（压栈）

- **作用**：将一个 8 字节（quad-word）的数据压入堆栈。
- **执行步骤**：
  1. 将 `%rsp` 减 8（为新数据腾出空间）；
  2. 把数据写入 `%rsp` 所指向的新地址。

- **例子**：  
  假设 `%rsp = 0x108`，`%rax = 0x123`，执行：
  ```asm
  pushq %rax
  ```
  → `%rsp` 变为 `0x100`  
  → 内存地址 `0x100` 处现在保存了值 `0x123`

- **等效于两条指令**：
  ```asm
  subq $8, %rsp      # 栈指针下移 8 字节
  movq %rax, (%rsp)  # 将值存入新栈顶
  ```
  但 `pushq` 更高效——它在机器码中只占 1~2 个字节，而上面两条指令共需约 8 字节。


####  `popq` 指令（出栈）

- **作用**：从堆栈顶部弹出一个 8 字节的数据，并将其加载到指定寄存器。
- **执行步骤**：
  1. 从 `%rsp` 指向的地址读取数据；
  2. 将 `%rsp` 加 8（恢复到上一个栈顶位置）。

- **例子**：  
  在刚才 `pushq %rax` 之后，执行：
  ```asm
  popq %rdx
  ```
  → `%rdx` 获得值 `0x123`  
  → `%rsp` 恢复为 `0x108`

- **等效于两条指令**：
  ```asm
  movq (%rsp), %rdx  # 从栈顶读取数据
  addq $8, %rsp      # 栈指针上移 8 字节
  ```

> 注意：被弹出的数据（如 `0x123`）可能仍留在内存地址 `0x100` 中，直到被后续操作覆盖。但从逻辑上讲，它已不属于堆栈内容，因为 `%rsp` 已不再指向它。



#### 🔹 其他重要说明

- 你可以**不通过 pop 直接访问堆栈中的其他位置**，使用标准内存寻址方式即可。  
  例如：
  ```asm
  movq 8(%rsp), %rdx   # 将栈中“第二个”元素（栈顶下方8字节处）加载到 %rdx
  ```

- 堆栈与程序代码、全局变量等共享同一块内存空间，因此可以用普通内存访问方式读写，但只有 `%rsp` 之上的部分才被视为“有效堆栈”。

####  核心要点速查表

| 概念 | 说明 |
|------|------|
| **堆栈增长方向** | 向**低地址**增长（向下） |
| **栈顶指针** | `%rsp` 始终指向**当前栈顶元素** |
| **`pushq`** | 先减 `%rsp` 8，再存数据 |
| **`popq`** | 先读数据，再加 `%rsp` 8 |
| **效率优势** | `pushq`/`popq` 是单条高效指令 |
| **内存残留** | 弹出后的数据仍可能留在内存中，但逻辑上已无效 |
| **用途** | 支持函数调用、返回地址保存、参数传递、局部变量分配等 |


这种机制是**函数调用系统的基础**：每次调用函数时，返回地址、参数和局部变量都会被自动压入堆栈；函数返回时再依次弹出，确保程序能正确回到调用点。

### **`leaq` 指令详解**

`leaq`（Load Effective Address）指令在形式上看起来像是一条从内存读取数据的指令，但实际上 **它完全不访问内存**。它的作用是 **计算一个内存操作数的“有效地址”（即地址值）**，并将这个地址直接存入目标寄存器。

#### 基本语法
```asm
leaq 源操作数, 目标寄存器
```
- 它会像处理内存引用一样解析“源操作数”的地址表达式，
- 但**不会去读取该地址中的内容**，而是把**地址本身**作为数值存入目标寄存器。

#### 举个例子
假设 `%rdx` 中的值是 `x`，执行：
```asm
leaq 7(%rdx,%rdx,4), %rax
```
这个指令会计算：
```
%rax = %rdx + 4 × %rdx + 7 = 5x + 7
```
 注意：这里没有内存访问，只是做算术！

#### 关键特点
- **不访问内存**：`leaq` 是纯地址计算，速度快，无副作用。
- **支持灵活的地址模式**：  
  x86-64 的地址格式为 `基址 + 变址×比例 + 偏移量`，  
  所以 `leaq` 能高效实现形如 `a*x + b` 的线性运算（其中 `a` 可以是 1、2、3、4、5、8、9 等组合）。
- **目标必须是寄存器**：不能写成 `leaq ..., (%rsp)`。
- **编译器常用技巧**：  
  即使程序逻辑与“地址”无关，编译器也经常用 `leaq` 来优化简单算术（比如乘加运算），因为它比多条 `add`/`imul` 更高效。

#### 常见用途
1. **生成指针**：例如计算数组元素的地址 `&arr[i]`。
2. **快速算术**：如 `x*5 + 3`、`x*9`、`x + y + 8` 等，用一条 `leaq` 完成。
3. **函数参数或局部变量地址计算**（在函数调用中非常常见）。

> `leaq` 表面上是“加载地址”，实际上是**用一条指令高效完成特定形式的整数加法和乘法（仅限乘以 1/2/4/8 及其组合）**，且**不访问内存**，是编译器优化的重要工具。
**this is only with no variant**


### 一、移位操作（Shift Operations）

在 x86-64 架构中，移位指令用于对整数进行左移或右移操作。移位量（即移动多少位）可以通过两种方式指定：

- **立即数（immediate value）**：直接在指令中写明移位位数。
- **%cl 寄存器**：这是唯一被允许用于指定移位量的寄存器（即使是 64 位程序也只能用 %cl 的低 8 位）。

x86-64 对移位量有特殊处理规则：  
对于一个 w 位宽的操作数（如 byte=8, word=16, long=32, quad=64），实际使用的移位量仅取自 %cl 的最低 m 位，其中 \(2^m = w\)。也就是说：
- 对 8 位数据（如 salb）：只使用 %cl 的低 3 位（最多移 7 位）
- 对 16 位数据（salw）：使用低 4 位（最多 15 位）
- 对 32 位数据（sall）：使用低 5 位（最多 31 位）
- 对 64 位数据（salq）：使用低 6 位（最多 63 位）

**举例**：若 %cl = 0xFF（即 255），则：
- salb 移 7 位（255 mod 8 = 7）
- salw 移 15 位（255 mod 16 = 15）
- sall 移 31 位
- salq 移 63 位

**移位类型**：
- **左移（Left Shift）**：`sal` 和 `shl` 是同义指令，效果相同——低位补 0。
- **右移（Right Shift）**：
  - `shr`：逻辑右移，高位补 0。
  - `sar`：算术右移，高位填充符号位（用于有符号整数，保持数值符号不变）。

目标操作数可以是寄存器或内存地址。


### 二、特殊算术运算（Special Arithmetic Operations）

x86-64 提供了对 128 位结果的支持，用于处理 64 位整数相乘或除法时可能溢出的情况。

#### 1. 乘法（Multiplication）

- **`imulq S`（单操作数形式）**：带符号全乘法。  
  - 要求一个操作数在 `%rax`，另一个为源操作数 S。
  - 结果：高 64 位 → `%rdx`，低 64 位 → `%rax`。
- **`mulq S`**：无符号全乘法，行为类似，但解释为无符号数。

> 注意：`imulq` 有两种形式——双操作数（截断为 64 位结果）和单操作数（生成 128 位结果）。汇编器根据操作数数量自动区分。


#### 2. 除法（Division）

- **`idivq S`**：带符号除法。
  - 被除数：128 位，由 `%rdx:%rax` 组成（%rdx 高位，%rax 低位）。
  - 商 → `%rax`，余数 → `%rdx`。
- **`divq S`**：无符号除法，行为类似，但解释为无符号。

**准备被除数**：
- 对于 **有符号除法**：需先用 `cqto` 指令将 `%rax` 的符号位扩展到整个 `%rdx`。
  ```asm
  cqto   # 等价于: if %rax < 0 then %rdx = -1 else %rdx = 0
  ```
- 对于 **无符号除法**：需先将 `%rdx` 清零：
  ```asm
  xorq %rdx, %rdx   # 或 movq $0, %rdx
  ```



### 四、其他细节

- **为什么用 `xorq %rcx, %rcx`？**  
  这是一种高效清零寄存器的方法（比 `movq $0, %rcx` 更短，通常只需 3 字节 vs 7 字节），常用于初始化或准备无符号除法。

- **寄存器复用**：编译器经常在不同阶段重用同一个寄存器存储多个中间变量（如 `%rax` 先存 3*z，再存 48*z，最后存返回值）。

- **数据类型与指令选择**：大多数算术/逻辑指令对有符号和无符号数行为一致（如加、减、与、或、异或、左移），**只有右移和除法需要区分**。

## 二、汇编代码 vs 机器码

* 在**汇编代码**里，跳转目标用的是 **标签（label）**，比如 `.L1`、`.L2`
* **汇编器（assembler）** 和 **链接器（linker）** 会：

  * 计算标签对应的真实内存地址
  * 把跳转目标编码进机器指令里

程序员一般不用关心这些编码细节，但理解它有助于：

* 看懂反汇编代码
* 理解链接（Chapter 7）的原理



## 三、跳转目标的两种编码方式

###  PC 相对寻址（最常用）

这是**最常见**的方式。

跳转指令中保存的是：

```
目标地址 − 跳转指令后面那条指令的地址 也就是一个偏移量（offset）。
```

特点：

* 偏移量可以用 **1 / 2 / 4 字节**表示
* CPU 执行时：

  * 取“下一条指令”的地址
  * 加上偏移量
  * 得到真正的跳转目标
 指令短. 代码可整体移动（可重定位）。



### 2️⃣ 绝对地址（较少用）

* 直接在指令中存放目标地址
* 通常用 4 个字节
* 不适合函数内部的频繁跳转



## 四、例子：带前跳和后跳的代码

### 汇编代码：

```asm
movq %rdi, %rax
jmp .L2
.L3:
sarq %rax
.L2:
testq %rax, %rax
jg .L3
rep; ret
```

### 逻辑说明：

* `jmp .L2`：向前跳
* `jg .L3`：如果 `%rax > 0`，向后跳（形成循环）
* 否则返回



## 五、反汇编中的 PC 相对偏移

反汇编显示：

```asm
3:  eb03    jmp 8
b:  7ff8    jg 5
```

### 解释：

#### `eb 03`

* `03` = +3
* 跳转目标 = 下一条指令地址 + 3

#### `7f f8`

* `f8` = −8（补码）
* 跳转目标 = 下一条指令地址 − 8

➡️ **向前跳 → 正偏移**
➡️ **向后跳 → 负偏移**

---

## 六、一个非常重要的细节

在 PC 相对寻址中，CPU 使用的 PC 是：

> **跳转指令执行完后的下一条指令地址**

❌ 不是跳转指令本身的地址

这是历史设计决定的。

---

## 七、为什么链接后偏移量不变？

链接后，函数被放到了新的内存地址：

```asm
4004d3: eb 03 jmp 4004d8
4004db: 7f f8 jg 4004d5
```

虽然：

* 指令地址全部变了

但是：

* **指令之间的相对距离没变**
* 所以 **偏移量完全一样**
 这就是 PC 相对跳转最大的优势。


## 八、关于 `rep; ret`

* `rep` / `repz` 通常用于字符串指令
* 在这里 **什么都不做**
* AMD 建议在 `ret` 前加 `rep`，有助于分支预测
* 不影响程序行为
* 本书中看到可以直接忽略

## 九、为什么 PC 相对跳转很重要？

* 指令更短（通常 2 字节）
* 代码可以随意搬家（可重定位）
* 非常适合循环和条件判断


**PC 相对跳转通过保存“跳多远”而不是“跳到哪”，让指令更紧凑、代码更灵活。**
